# Project status

- Project: **VortexDM** (C++23)
- Status: **IN_PROGRESS**
- Current implementation phase: **Phase 6 — responsive Qt UI and release**
- Supported targets: Windows 10/11 x64, Linux x64 and Android 9+ arm64-v8a. macOS is explicitly excluded.
- Android ad blocking: use the original, unmodified Raymond Hill uBlock Origin distributed through Mozilla Firefox for Android. The VortexDM Android app/Bridge handles download handoff; it does not ship a replacement filter engine. Embedded GeckoView + upstream uBO remains an optional, unverified experiment.
- Completed implementation areas: core/platform scaffolding, SQLite WAL persistence, segmented HTTP transfers and recovery, yt-dlp extraction profiles, HLS/DASH manifest parsing, bounded cancellable HTTP resource fetching for manifests/keys, ffmpeg mux primitive, desktop Native Messaging, Android authenticated loopback IPC, foreground-service scaffold, Android 10+ MediaStore export, and responsive Qt/QML shell.
- Recent additions: IPC v1 now exposes `task_status` through both desktop Native Messaging and Android loopback; the Bridge popup polls recent task status/progress while open. This is pull-based synchronization, not unsolicited push. Android 9 SAF document-picker/copy flow is wired through a custom QtActivity and JNI (physical-device validation pending); queue dispatch ignores inactive queues and unassigned downloads now reliably fall back to the default queue; HLS parsing now requires the header at the beginning and resets AES-128 state on METHOD=NONE; DASH SegmentTemplate declarations are merged through Period, AdaptationSet and Representation levels, with child attributes overriding inherited values and the nearest SegmentTimeline taking precedence.
- Remaining implementation gaps: end-to-end HLS/DASH download-to-mux orchestration; full queue scheduling/category routing; Android 9 SAF physical-device validation; unsolicited status push (popup polling is implemented); desktop settings/dialog polish; Android device acceptance; installers and signed APK/AAB; SLO benchmarks.
- Recent maintenance: worker shutdown now uses the worker-owned atomic stop flag; the task monitor uses a portable std::thread plus an atomic stop flag (no std::jthread dependency).
- CI delivery: GitHub Actions now uses per-branch/per-PR concurrency with `cancel-in-progress: true`, so newer commits supersede stale runs. Successful desktop builds publish CLI/native-host binaries, Android publishes the ARM64 core static library, and Browser Bridge publishes Chrome MV3, Firefox MV3 and Firefox Android MV2 packages as downloadable workflow artifacts (30-day retention). CI jobs also have bounded execution times to prevent stuck builds. This does not yet produce a signed Android APK/AAB; Qt Android packaging/signing remains a release gap.
- Verification policy: implementation-first. Consolidated tests/platform builds are deferred until implementation is complete. Do not mark any phase DONE without passing CI and acceptance evidence.
- Latest verified CI: DASH template inheritance commits 1d519f35, 692b7c77 and docs commit ca3cebfd passed. The bounded resource-fetch test initially failed because `tests/test_core.cpp` omitted `vortex/download_engine.hpp`; the include has been added in 4f44632c. The corrected core/status-sync run and artifact publishing changes are being validated on the current head; no result is assumed until all jobs complete.
- Next action: complete HLS/DASH transfer orchestration, queue scheduling, optional extension status push and release polish; then execute and repair the complete Windows/Linux/Android and sanitizer validation matrix.
