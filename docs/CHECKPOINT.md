# Durable checkpoint

- Current phase: 6 of 6 (IN_PROGRESS; final validation intentionally deferred until implementation phases are complete).
- Supported targets: Windows x64, Linux x64 and Android arm64-v8a. macOS is explicitly excluded by CMake.
- Android ad blocking: use the original Raymond Hill uBlock Origin distributed by Mozilla for Firefox for Android. Vortex Browser Bridge disables its own Android filter engine and handles download handoff only. Embedded GeckoView + upstream uBO remains an experimental optional proof-of-concept; do not bundle a modified clone.
- Phase 1 baseline: C++23 core, CMake/vcpkg, protocol v1, crash-safe file writer, URL validation and initial platform CI. Existing CI evidence is recorded in progress.json; new changes have not yet received the final consolidated test pass.
- Phase 2: SQLite WAL schema v1-v2, downloads/streams/segments/queues/categories/toolchain/settings, atomic queue claims, parallel libcurl ranges, bounded retries, fsync-before-SQLite segment checkpoints, exact Content-Range validation and recovery of missing ranges. The active queue worker now reconnects persisted checkpoints after process restart; if the journal/file is invalid it falls back to a clean full transfer.
- Phase 3: shell-free process runner, yt-dlp JSON metadata parser, persisted local profiles, SHA-256-verified staged activation/rollback, expired URL refresh, queued single/playlist extraction through the configured yt-dlp binary or Python module. Session cookies are deliberately not collected or persisted; authenticated/private media extraction is not supported yet.
- Phase 4: HLS master/media playlist parser (including relative URI and AES-128 key metadata), DASH SegmentTemplate/Timeline/List/Base parser, and shell-free ffmpeg stream-copy muxer. The remaining gap is end-to-end HLS/DASH download-to-mux orchestration and its acceptance fixtures.
- Phase 5: desktop Native Messaging host and Android authenticated 127.0.0.1 loopback IPC, queue-aware handoff, batch chunking, task pause/resume/cancel, background download worker, durable byte progress, yt-dlp task execution and Windows/Linux host registration scripts. See docs/NATIVE_MESSAGING_INSTALL.md. Android uses an ephemeral port and 256-bit per-launch key shown in the app; Bridge settings must be updated after app restart. App-to-extension live status push and full queue scheduling remain pending.
- Phase 6: Qt/QML task list, named queues, yt-dlp profile configuration, Android responsive layout, Android dataSync foreground-service scaffold and MediaStore export for Android 10+. Android 9 public Downloads export, signed installers/APK/AAB, device validation and SLO benchmarks remain pending.
- Android files are initially stored under the app-private Downloads directory. Completed files can be exported to Downloads/VortexDM on Android 10+. Android 9 export still needs SAF/legacy storage support.
- Test policy for this work session: implementation first; run the consolidated tests and platform builds only after all planned implementation phases are complete. No claim of a passed test is made for unexecuted checks.
- Next implementation priorities: finish HLS/DASH-to-mux orchestration, queue scheduling/category routing, app-to-extension status push, Android 9 export and release packaging. Then run the complete final test matrix and fix every failure before marking phases DONE.
